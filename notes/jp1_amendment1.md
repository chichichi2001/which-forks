## 変えること

- **C1（精度）**：1B と 3B を float32 で読み込む（`P.MODELS` の dtype）。attention は eager のまま。TF32 は使わない：作業プロセスと G0 で、推論の前に `torch.backends.cuda.matmul.allow_tf32 == False` と `torch.get_float32_matmul_precision() == "highest"`（どちらも PyTorch の既定。診断と確認でこの値だった）を確かめ、違えば止める（`JP1_STOPPED_VERSION_MISMATCH`）。
- **C2（引き直しの step）**：K 本の引き直しの batched step を `pork/jp1_shared_prefix.py` の `torch_shared_prefix_batch` に替える。最初の呼び出し（K 行とも同じ先頭）では先頭を1行で1回だけ計算し、KV キャッシュを K 行に写す（`DynamicCache.batch_repeat_interleave`、transformers 5.18.0）。2歩目からは今までと同じ K 行の計算。`generate_batch`、乱数の流れ、引き方、alt の決まり、終わった行の扱いは変えない。使う場所：本番の作業プロセス、事後再生監査、G0 の B1 と時間の見積もり。
  - 土台の道（E2・G1 が見る1行の step）は変えない。
  - B1（batched と1行の一致）は新しい step で見る。最初の歩は作りから同じになり、2歩目からの K 行の計算を見ることになる。
- **C3（作業プロセスの確かめ）**：`jp1_runner` の dtype の確かめ（いまは bfloat16 を決め打ち）を、`P.MODELS` の dtype に合わせる。
- **C4（G0 の2回目）**：G0 を最初から全部やり直す（版、付録C・D、GPU と Python の一致、G0 の正解率、E2・G1・B1、時間と CU）。土台の道が float32 になるので、正解率も float32 で測り直し、**計画の切り替えの決まり（0.20 未満なら 3B に1回だけ）は2回目の数に当てはめる**。1回目（bfloat16）の数は記録と報告に残す。
  - 2回目で 3B に切り替わったときは、3B も float32 で、同じ止める線を当てはめる（作業の数は下の M1 で決める。収まらなければ計画のとおり止める）。
- **C5（G0 の2回目に足す確かめ。どれも推論で本番の問題は使わない）**：
  - **B2（新しい step の再現性）**：同じ先頭・同じ乱数で新しい step を2回回し、K 本がすべて同じ。違えば止める（`JP1_STOPPED_PRECHECK`、新しい止まり方）。
  - **M1（作業2つのメモリ）**：本番と同じく別々のプロセスで作業2つを同時に、いちばん長い列（頼み方の最大＋512）で回し、2つとも最後まで動く。動かなければ止める（`JP1_STOPPED_PRECHECK`）。使用量は記録する。
- **C6（本番のノートブック）**：作業プロセスを動かしているあいだ、ノートブック本体は GPU にモデルを置かない（M1 の余裕が 2.5 GB しかないため）。

## 変えないこと

- 問題、乱数の種、K（32）、STRIDE（8）、温度（1.0）、引き方、読み取り・語の種類の決まり、判定とラベル、分析、ブートストラップと並べ替え、事後再生監査（言語ごと5問×3位置、2問以上ずれたら `JP1_PROTOCOL_FAIL`）と語の種類の監査、ガード、止める線（1冊 ×2.7 で 14 時間、全体 45 CU）。
- 事後再生監査は、本番と同じ新しい step で作り直す（同じ関数どうしを比べる）。

## 影響と開示（報告に書くこと）
