## ひとことで（数式なしの要約）

- DP1〜DP5 は、英語の算数の問題（GSM-Symbolic）と、英語中心のモデル（OLMo-2 1B、Gemma-2-2b-it）でやった。
- JP-1 は、**日本語と英語の両方が得意なモデル（Sarashina2.2）**に、**同じ算数の問題を日本語と英語で**解かせて、分かれ道を比べる。
  - モデルと元の問題が同じなので、モデルの違いは混ざらない。ただし、言語を変えると、訳・指示の文・トークンの数・正解率も一緒に変わる。なので、結果は「**同じモデル・対応する問題での、言語の条件による観測された差**」として書き、「言語だけを変えた実験」とは言わない（一緒に変わるものは副次で並べて報告する）。
  - 問題は MGSM（GSM8K の問題を10言語に訳したもの）。日本語版と英語版が1問ずつ対応している。
- 問い：
  - **主A（土台）**：DP5 で見つけたこと（重みづけ・逆向き・数字の語）が、日本語でも英語でも出るか。そして、逆向きの強さが言語で違うか。
  - **主B（格上げ候補）**：分かれ道は、言語が変わっても「推論の中身（数字・計算の言葉）」に集まるか。それとも日本語では「つなぎの言葉（助詞など）」に、ふだんの割合より多く集まるか。
  - **副次C**：日本語は空白で単語を区切らないので、分かれ道が単語の途中のトークンに現れやすいか。
- 位置づけ：「Which forks?」の追加の確かめ（おまけ）として始める。主B のラベルが面白ければ、別の短い論文に格上げする道を残す（［決定7］）。
- 扱うのは算数の問題だけ。危ない内容はない。問題の中身とトークンの中身は表示しない（数・ID・ハッシュだけ）。

   - 土台の道の答えが読めなかった問題は、その言語の分析から外す（DP5 と同じ）。外した数は報告する。
4. **土台の道・位置・引き直し・量・ラベル**：DP5 と同じ。
   - 貪欲法、最大512トークン。エントロピー・p1・p2・1位と2位の語・数字かどうかを記録する。

   - d_s、e_alt、e、d_plain。上位15%のラベル（同じなら行の小さい順、位置の小さい順）。
   - **言語ごとに別々に**、全部の計算をする（上位15%も言語ごとに決める）。
   - 引き直しの答えの読み取りも、その言語の読み取りの決まり（3.）を使う。
5. **語の種類**（主B・副次C のため。土台の道の各位置 t のトークンについて、コードが自動で決める。中身は表示しない）。これは**辞書と品詞による操作上のラベル**で、その語が文脈の中で本当に計算の役目をしているかを判定するものではない。
   - **トークンの開始位置**：土台の道の応答のトークンを $x_0, x_1, \dots$ とし、応答全体を文字列に戻したものを T とする。トークン t の開始位置は、$x_0 \dots x_{t-1}$ を文字列に戻した長さ。ただし、その文字列が T の先頭部分と一致しないとき（バイトの途中で切れたときなど）は「分類できない」（理由 `PREFIX_MISMATCH`）。終わりの位置も同じように $x_0 \dots x_t$ から決める。
   - **見る文字**：トークンの開始位置から終わりの位置までのうち、最初の空白でない文字。空白（改行を含む）しかないトークンは、種類「**空白**」にする（分かれ道が改行に来ることもあるので、分母から外さない）。長さが0のトークンは「分類できない」（理由 `EMPTY`）。
   - **語**：見る文字を含む語。T を区切って、文字の位置で対応させる（英語は T 全体を一度に区切る。日本語は下のとおり行ごと）。
     - 英語：空白で区切った語。語の前後から、決めた記号（`. , ; : ! ? " ' ( ) [ ] { } “ ” ‘ ’ …` と — ）を落とす。落とすと空になる語（記号だけの語）は、元のまま使う。
     - 日本語：形態素解析（`fugashi` ＋ `unidic-lite`、版は G0 の前に固定）で区切った形態素。T を改行（`\n`）で行に分け、**行ごとに別々に**形態素解析して、各形態素の位置を T の中の位置に戻す（改行そのものは語にしない）。
     - 日本語で、形態素の表層形を T の文字に対応させられなかったとき（解析器が文字を落とす・変えるなど）は、その応答のすべてのトークンを「分類できない」（理由 `MORPH_ALIGN_FAIL`）とする。実験は止めず、件数を報告する（下の「分類できた割合の線」に入る）。語を勝手に捨てて分母を変えることはしない。
     - 1つのトークンが2つ以上の語にまたがるときも、見る文字を含む語だけで決める（二重に数えない）。またがった数は報告する。
   - **種類**は次の順に見て、最初に当てはまったもの：
     1. **数字**：
        - 英語：記号を落とした語が、十進数の数字（Unicode の数字）を含む。または、小文字にした語が「数の言葉の一覧」（付録B）に入る。
        - 日本語：形態素が十進数の数字（半角・全角）を含む。または、UniDic の品詞が「名詞」で、その下の分類が「数詞」。漢数字を**含むだけ**の語（「一緒」など、品詞が数詞でないもの）は数字にしない。
          - 分かっている限界（C0 で確かめた）：辞書が語を細かく区切り、その一部を数詞とするときは、その一部が数字になる（「万年筆」は「万（数詞）・年・筆」に区切られ、「万」が数字になる）。辞書による操作上のラベルとしてそのまま数え、直さない（文脈で「1万年」と見分けられないため）。
     2. **計算の言葉**：語が「計算の言葉の一覧」（付録B）に入る。英語は、小文字にして記号を落とした語で照らし合わせる（記号だけの語は、その記号のまま）。日本語は、形態素の見出し語（UniDic の lemma）と、書かれた形（表層形）のどちらかが一覧に入れば当てはまる。
     3. **つなぎの言葉**：英語は NLTK の英語の stopwords（版は G0 の前に固定）に入る語。日本語は、品詞（大分類）が「助詞」または「助動詞」の形態素。計算の言葉の一覧と stopwords の両方に入る語（`each` など）は、順番どおり計算の言葉になる。
     4. **その他**。
     - （空白だけのトークンは、上の 1.〜4. の前に「空白」になる。）
   - 「分類できない」位置（`PREFIX_MISMATCH`・`EMPTY`・`MORPH_ALIGN_FAIL`）は、主B・副次C の集計の分母から外し、理由ごとの数を報告する。外したことで偏らないよう、主B には下の「分類できた割合の線」を置く。
   - **単語の途中か**：見る文字が、語の先頭の文字でなければ「単語の途中」。種類が「空白」のトークンには見る文字がないので、単語の途中かどうかは決めず、S4 の分母から外す（主B では「空白」として数える）。
   - 語の種類と読み取りの決め方は、無害な例文（付録C・付録D。ベンチマークとは関係ない）で確かめる。凍結の前に C0 で一度、G0 でもう一度。G0 で付録の答えと1つでも違えば止める（`JP1_STOPPED_CATEGORY_RULE` / `JP1_STOPPED_READOUT_RULE`。直すなら新しい計画として書く。本番の途中で分類や読み取りのコードを直さない）。

## 問い（主）

- **主A（DP5 の再現と、言語の違い）**：言語ごとに、DP5 の主1・主2・主3 と同じ計算をする（その言語で分析に入った問題すべてを使う）。
  - A1（重みづけ）：エントロピーの問題内 AUROC の差（top d_s − top e_alt）。
  - A2（逆向き）：エントロピーの「top e」に対する問題内 AUROC。
  - A3（数字の語）：top e の AUROC の（数字以外の位置だけ − 全部）と、top e に入る割合の（数字 − 数字以外）。数字かどうかは DP5 と同じトークン単位の印を使う（上の語の種類ではない）。
  - **A4（言語の違い）**：A2 の（日本語 − 英語）。両方の言語で AUROC が計算できる同じ問題について、問題ごとの差を平均する（下の「区間と、組の決め方」の P_A4）。
- **主B（分かれ道は推論の中身に集まるか）**：どれも、対応する問題の組で計算する。
  - B1（中身への集まり）：言語ごとに、top d_s の位置のうち「数字＋計算の言葉」の割合 −（全部の位置のうち「数字＋計算の言葉」の割合）。
  - B2（つなぎの言葉への集まりの言語差）：言語ごとに、**つなぎの言葉への集まり**＝（top d_s の位置のうち「つなぎの言葉」の割合 − 全部の位置のうち「つなぎの言葉」の割合）を出し、その（日本語 − 英語）。
    - 生の割合の差ではなく、ふだんの割合を引いた値を比べる。日本語は助詞が多いので、生の割合では、分かれ道に好みがなくても差が出てしまうため（独立レビューの P4）。生の割合の差は副次（S10）で出す。

## 判定（事前に決めるラベル）

### 区間と、組の決め方

- 区間はすべて、問題を単位にしたブートストラップ 2,000 回の両側95%（種 SEED_JP_BOOT）。
- **言語ごとの量（A1〜A3）**：DP5 と同じ（その言語で分析に入った問題を引き直し、各問題の値を、引いた問題で平均する。AUROC が計算できない問題は、その量から外れる）。
- **A4（同じ問題での日本語と英語の差）**：
  - 集合 P_A4 を先に決める：日本語と英語の**両方で**分析に入り、**両方で** A2 の問題内 AUROC が計算できる問題（正と負の位置が両方ある問題）。
  - 問題ごとに差（日本語の AUROC − 英語の AUROC）を出し、その平均を A4 とする。区間は P_A4 の番号を引き直して作る（P_A4 の問題はどれも差を持つので、どの回でも値が決まる）。
  - P_A4 の問題数が20未満なら、A4 は `AWAY_LANGUAGE_UNDEFINED`（理由 `JP1_TOO_FEW_PAIRED_ITEMS`）。
- **主B（B1・B2）**：
  - 集合 P_B を先に決める：日本語と英語の**両方で**分析に入り、**両方で**分類できた位置が1つ以上ある問題。
  - 区間は P_B の番号を引き直し、同じ番号の日本語と英語を一緒に使う。割合は、引いた問題の位置をまとめて数える（同じ問題を2回引けば2回数える）。上位15%のラベルは、言語ごとに、その言語で分析に入ったすべての位置で決めたものを使う（DP5 と同じ）。
  - P_B の問題数が20未満なら、主B は `REASONING_LOCALIZATION_UNDEFINED`（理由 `JP1_TOO_FEW_PAIRED_ITEMS`）。
  - **分類できた割合の線**：どちらかの言語で、分類できた位置の割合が、全部の位置または top d_s の位置で 0.90 を下回れば、主B は `REASONING_LOCALIZATION_UNDEFINED`（理由 `JP1_CATEGORY_MISSINGNESS`）。この割合は、**P_B で絞る前の**、日本語と英語の両方で分析に入った問題の集合 P の位置で数える（分子は分類できた位置、分母は P の問題の、その言語の調べた位置すべて。応答のすべてのトークンが `MORPH_ALIGN_FAIL` になった問題も、分類できた位置 0 として分母に入る。top d_s のほうは、そのうち top d_s の位置）。この線を通ったあとで、B1・B2 の値が決まる問題だけを P_B に入れ、P_B の問題数が20以上という条件は別に見る。P の外の問題を含めた割合を、P での抜けを打ち消す根拠にはしない。分類できた割合は、言語ごとに、全部の位置・top d_s の位置で、理由ごとに報告し、P から P_B へ移るときに外れた問題の数（理由ごと、`MORPH_ALIGN_FAIL` の数を含む）と位置の数も報告する。
- **値が決まらない回**：ブートストラップのある回で値が決まらない（引いた問題に top d_s の分類できた位置が1つもない、など）ときは、その回を外す（DP の区間の作り方と同じ）。外さずに残った回が 1,900 回（95%）に届かなければ、そのラベルは `<ラベルの名前>_UNDEFINED`（`JA_`・`EN_` のつく A1〜A3 では、たとえば `JA_MAIN2_UNDEFINED`。A4 は `AWAY_LANGUAGE_UNDEFINED`、主B は `REASONING_LOCALIZATION_UNDEFINED`）とし、理由と分母を報告する。残った回の数は、すべての量で報告する。
- 言語ごとの問題数、P_A4・P_B の問題数、AUROC が計算できた問題数を、どれも報告する。A4 と主B で問題数が違えば、分けて書く。

### ラベル

- A1〜A3：言語ごとに、DP5 と同じ線とラベル（`WEIGHTING_EXPLAINS_FLIP` など）。ラベルの頭に `JA_` か `EN_` をつける。
- A4：
  - 区間が −0.10〜+0.10 に収まる → `AWAY_LANGUAGE_INVARIANT`（決めた幅の中で、同じと言える）

## 付録C 語の種類を確かめる例文

トークンの決まりの確かめ（付録C のすべての例文で）：
- どのトークンにも、ちょうど1つの種類か、分類できない理由（`PREFIX_MISMATCH`・`EMPTY`・`MORPH_ALIGN_FAIL` の3種類）がつく。
- 付録C の例文はふつうの文なので、分類できない理由（3種類とも）は**0件**であること（全部が分類できないのに合格、ということを起こさない）。
- **はっきりした答えの確かめ**：上に挙げた確かめる語のそれぞれについて、見る文字がその語の中にあるトークンが**すべて**、上に書いた種類になっていること。トークンの区切り方を知らなくても書ける確かめなので、1つのトークンが2つ以上の語にまたがる場合も、ここで確かめられる（またがったトークンは、見る文字のある語の種類になっていなければならない）。

- 2つ以上の語にまたがるトークンの数と、単語の途中のトークンの数を出す（決めた答えはない。数を記録するだけ）。

## 付録D 答えの読み取りの判定表

決まり（日本語）：
1. **目印**：応答の中の、最後の「答え」。
2. **数**：目印の後ろにある、最初の「数の並び」（読めたときの理由は `OK_MARKER`）。数の並びは、正規表現 `[-−－]?[0-9０-９][0-9０-９,，]*(?:[.．][0-9０-９]+)?`（符号は半角・数学の負号・全角の3種類、桁の区切りは半角・全角のカンマ、小数点は半角・全角）。漢数字は数として読まない。
3. 目印があるのに、後ろに数の並びがない → 読めない（理由 `NO_NUMBER_AFTER_MARKER`）。
4. 目印がない → 全文の最後の数の並び（理由 `FALLBACK_LAST_NUMBER`。読めたことにする）。数の並びがひとつもない → 読めない（`NO_NUMBER`）。
5. 選んだ数の並びのすぐ後ろが「万」「億」「兆」 → 読めない（`KANJI_MULTIPLIER`）。すぐ後ろが「分の」 → 読めない（`FRACTION`）。
6. **値**：選んだ数の並び**だけ**を NFKC で半角に直し、`−` を `-` に直し、カンマを除いて十進数にする。`answer_number` と十進数で比べる。
7. **答えの開始位置**：選んだ数の並びの、元の文字列での開始位置（符号があれば符号）。

英語は DP と同じ（`extract_prediction` と `answer_span`。目印は大文字小文字を区別しない「final answer」、数の並びは `-?\d[\d,]*(?:\.\d+)?`、目印がなければ最後の数）。理由コードは同じ名前で数える（`KANJI_MULTIPLIER`・`FRACTION` は日本語だけ）。
