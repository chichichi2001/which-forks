# DP2 実装メモ（凍結後・本番前）

ゲート：`notes/dp2_real_forks_gate.md`（凍結 sha256 `15249f22…`、コミット `0fff4f7`）。ゲート文書は変えていない。
このメモは、ゲートが細かく決めていなかった点を、**本番のトークンを1つも作る前に**どう実装したかの記録。

## ゲートの読み方（解釈）
- **60テンプレート**：`sorted(random.Random(202610061642).sample(range(100), 60))` を、**並べたテンプレートidの添字**として使う（DP1以前と同じ扱い）。
- **監査の3点**：問題ごとに `random.Random(202610061644 + (行+1)×1,000,003)` で点の番号から3つ選ぶ（DP1の監査位置と同じ作り方）。
- **仕事の単位**：ゲートは（行、点）。実装では、点を決めるのに必要な土台の道も1つの単位にした（結果は同じ）。
- **区間のない問題**：土台の答えが読めない問題に加えて、答えの先頭が位置0の問題（a = 0）も区間がないので分析から外れる。両方の数を `items_without_windows` として報告する。
- **ラベルが出せないとき**：両方の種類の区間を持つ問題が1つもなく区間が作れないとき、ラベルは `None`。プローブの学習の分割に片方の種類しかないなど、主2が計算できないときは、理由を記録して主2を `None` にする（主1と監査・ガードの判定は出す）。
- ガードが外れたときは、参考のラベル（`labels_before_audit`）も出さない。

## 並列（取りに行く方式）の安全策
- 単位のファイルには時刻を入れない（所要時間は作業プロセスのログだけ）。テストで、取りに行く順番を3通り変えたとき、途中で止めて再開したとき、5プロセスを同時に走らせたとき（レビューの追加検査）に、全ファイルが**バイト単位で一致**することを確かめた。ゲートの条件を満たすので、固定の割り振りには戻さない。
- 途中で落ちた作業プロセスの鍵：鍵に書いたプロセスが死んでいて、単位のファイルもまだないときは、別のプロセスが引き継ぐ。2つが同時に引き継いでも、同じバイト列を原子的に書くだけなので害はない。
- Driveの読み込みの一時的なエラーは、数回読み直す。起動前に、検証に通らない単位のファイル（VMが落ちて途中で切れたものなど）は、消さずに `quarantine/` へ移して記録し、計算し直す。
- 60分間どの単位も終わらなければ、セル7が作業プロセスを止めて知らせる。
- 再開時、並列数が前回と違ってもよい（結果のファイルは並列数に依存しない）。GPUの種類は、最初の単位を作ったあとは変えない（DP1と同じ）。

## 時間の見積もりの注意
- セル6の見積もりは、1プロセスの1ステップの時間を並列数でそのまま割っている（DP1と同じ）。GPUが詰まると実際は遅くなりうる。セル7の進み具合で確かめる。
