# DP4 実装メモ（凍結後、コードを書くときに決めた細部）

- ゲート：`notes/dp4_weighting_gate.md`（sha256 4a8570c2…7828、凍結 644ef87）。ゲートの内容は変えていない。
- **alt の最初の1語**：ゲートでは「t の位置の1位の語（土台の語）だけを −∞ にしてから pure_sample で引く」と書いた。実装では、確率の大きい順に並べた分布から**土台の語 toks[t] を取り除き**、残りを足して1になるように直してから、同じ「U を超える最初の累積」の規則で引く（`d4.alt_sample`、参照は `d4.ref_alt`）。
  - −∞ にするのと数学的に同じ。
  - 取り除く方式にしたのは、丸め誤差で「どれも超えないときは最後の語」になる場合にも、土台の語が選ばれないようにするため。
  - 万一 alt の最初の語が土台の語になったら、作業プロセスを止める（assert）。
  - 取り除くのは、記録した土台の語そのもの。まとめて計算したときの logits の1位が、浮動小数の差で別の語になる場合でも、ゲートの「土台の語」の定義に従う。
- **p1**：土台の道を作るとき、DP1 の `step_signals` が出す p1（1位の確率）を各ステップで記録する（DP3 までの土台の記録に1列足しただけ）。
- **層別の確認の区間**：「区間が [−0.02, +0.02] の外に出たら」を、下限 < −0.02 または上限 > +0.02 と読んだ（一部でもはみ出したら `DP4_ESTIMATOR_MISMATCH`）。
- **強制入れ替え**は計算しない（ゲートどおり）。そのため、監査は4種類の引き直しだけを照合する。
- **時間の見積もり**（セル6）：4種類 × 32本のまとめた計算と、その前の読み込み（prefill）を位置ごとに数える。止める線は「ふつう × 2.7 > 14時間」。
- **テスト**（`tests/test_dp4.py`）：
  - 問題の重なりなし（Q8T・DP1・DP2・DP3）。
  - alt の引き方と参照の一致（同点や u≈1 を含む）。
  - 仕事を取りに行く方式で、結果のファイルがバイト単位で一致すること（順番を変えた場合、3つのスレッドで同時に動かした場合、途中で止めて再開した場合）。
  - 監査の再生。
  - 分析の形（重みづけがある合成データで `WEIGHTING_EXPLAINS_FLIP`、free をずらすと `estimator_ok` が False になること）。
