## きっかけ
- DP2 の副次 S2：問題文を読み終えた直後の 12 層目の状態から、リッジ回帰で「落ち幅が最大の区間の相対位置」を当てると、スピアマン 0.420 [0.183, 0.620]（予想は 0.2 未満）。
- これが「モデルは読んだ時点で、どこで詰まるかを知っている」なのか、もっと安い説明なのかを切り分ける。

## 安い説明の候補（これを順に潰す）
1. **「崩れるかどうか」の取り違え**：落ち幅がどこにもない問題（すべて d ≤ 0）では、最大の区間は「最初の区間」になり、相対位置は 0 になる。そういう問題は q(0) が小さい（簡単な問題）。隠れ状態は q(0) を当てられる（0.462）ので、「位置」ではなく「崩れるかどうか」を当てているだけかもしれない。**一番あやしい。**
2. **問題文の見た目**：問題文の長さ、数字の個数、文の数。長い問題ほど崩れる位置が後ろ、などの関係があれば、隠れ状態は文の長さを知っているだけ。
3. **土台の道の長さ**：相対位置は a（答えの位置）で割っている。a は読んだ時点では分からないが、問題文から予想しやすい量。

## やること（1冊の小さなノートブック。GPU不要、CPUのランタイムで回る）
- DP2 の単位ファイル（Drive）と OLMo-2 1B（DP2 と同じ版）を使う。プロンプト末の 12 層目の状態を、60問ぶん CPU で読み直す（1問1〜2秒）。DP2 の GPU の値とは小数点以下で少しずれるので、DP2 の予測の再現（スピアマン 0.420 前後）を最初に確かめる。
- 問題の中身は表示しない（特徴量はコードの中で数えるだけ）。

### 目標（当てるもの）
- T1：落ち幅が最大の区間の相対位置（DP2 の S2 と同じ定義）。
- T2：q(0)（比べるため）。

### 予測に使うもの（すべてテンプレート単位の5分割の外側の予測。分け方・リッジの強さ・ブートストラップは DP2 と同じ）
- A 安い：プロンプトのトークン数、問題文の数字の個数、文の数、問題文の文字数。
- B 隠れ状態（DP2 の S2 と同じ）。
- C 隠れ状態＋安い。
- 比べる：C − A のスピアマンの差（テンプレート単位のブートストラップ 2,000 回）。

### 説明1を潰すための切り分け
- (i) **崩れる問題だけ**：最大の落ち幅が 0.25 以上（本当の分かれ道がある）問題だけで、B と C − A をもう一度。
- (ii) **q(0) を引いた残り**：T1 を q(0) で回帰した残り（外側の予測で）を当てる。
- (iii) 参考：隠れ状態から a（答えの位置）を当てられるか。T1 と a の相関。

### 対照
- 並べ替え：T1 を問題の間でランダムに並べ替えて B を 200 回作り直し、0.420 がその分布のどこにあるか。
- 層は 12 層目だけ（DP2 と同じ）。ほかの層は見ない（あとから層を選ぶと、当たりを探すことになるため）。

## 生き残りの基準（事後なので「ラベル」ではなく目安）
- **生き残る**：(i) の問題だけでも B が 0.3 以上、かつ C − A の区間の下限が 0 より大きい。かつ (ii) でも 0 より大きい。
- **安い説明で説明できる**：(i) か (ii) で 0 付近まで落ちる、または C − A が 0 をまたいで A だけで同じくらい当たる。
- どちらでもなければ「はっきりしない」。60問では区間が広いので、これがいちばんありそう。
