## 0. この実験で何を確かめるか（と、確かめないこと）

CR-2 の見直し（探索的）で、次の形が見えた。

- 「外から測ったばらつき」u が分かれ道を見分けて見えたのは、ほぼ「その場所で別の単語が出るか」による。別の単語が出る 264 語の中では、u の見分けは偶然と区別がつかなかった。
- 264 語の中で、どれが分かれ道になるかは、ほぼ g（別の単語が出たとき答えが変わる度合い）で決まる。ただし g は数本の応答から出した雑音の大きい数。

CR-3 は、この 264 語について、**別の単語を書かせて（プリフィル）続きを新しく引き直し、g を直接・多めの本数で測る**。問いは 3 つ（3.）。

- **確かめないこと**：別の問題・別のモデルで同じことが起きるか（同じ 90 問・同じ 264 語を使う）。「探索で見えた形」を、**新しく引いたデータ**で確かめるだけで、一般化はしない。264 語は CR-2 のデータで選んだもので、その選び方を含めて結果を読む。
- 見直しの数（X1〜X6）は、問いと予想を立てるのに使った。CR-3 の判定には使わない。

## 1. データとモデル（CR-2 と同じ）

- 問題：CR-2 の最終の 90 問（`final_items_sha256` 9ffd511c…）。土台の道（温度 0 の応答）も CR-2 と同じもの（G1 の記録、`text_sha256` で照合）。
- モデル `claude-haiku-4-5-20251001`、SDK 1.13.0、最大 1,024 トークン、温度・top_p は指定しない（CR-2 の定義 7）。プロンプトは CR-2 と同じ（`PROMPT_SHA256` で照合）。バッチ API。
- 単位・切れ目・答えの読み取り・「変わった」の数え方は CR-2（＝CR-1 の定義 5・6・8、新しい定義 10・14）と同じ。読めない応答は「変わった」に数える。

## 2. 定義

- **D1 対象の単語 W**：CR-2 の確かめる単語（604 語）のうち、CR-2 の組B（切れ目 w − 1 から 18 本）で、新しい定義 10 で「s_w を書かなかった」応答が 1 本以上あった単語（n_diff(w) ≥ 1）。凍結した CR-2 のコードで CR-2 の生の結果から作り直す（見直しでは 264 語。違えば止まる）。
- **D2 CR-2 の分かれ道のラベル** lab2(w)：CR-2 の定義 13 を CR-2 の 604 語に当てたもの（G3 と同じ。92 語、すべて W に入る）。固定し、CR-3 では決め直さない。
- **D3 別の単語（プリフィルに使うもの）**：W の各単語 w について、CR-2 の組B の切れ目 w − 1 の応答のうち s_w を書かなかったものの「最初の単位」f（定義 14、`\s*\S+`）を集める。
  - 空・空白だけ（f が None）は除く。f の先頭の空白を落とした文字列でまとめ、**本数の多い順**、同数なら**その文字列の sha256 の小さい順**に並べる（中身で選ばない）。
  - a1(w)：1 番目のまとまり。a2(w)：2 番目のまとまり（あれば）。
  - プリフィルに使う文字列は、そのまとまりの中で一番多い元の形（先頭の空白を含む）。同数なら sha256 の小さい順。
  - a1 がない単語（別の応答がすべて空・空白だけ）は「書かせる別の単語なし」として、A1・A2 の対象から外す（数を報告）。
  - 記録には文字列も、1 語ずつの sha256 も書かない（短い単語の sha256 は辞書で引けば中身が分かるため）。書くのは本数と順位と、**全部のプリフィル文字列をまとめた 1 つの sha256**（正規化した JSON の並び）だけ。3 つの照合（5.）はこのまとめたハッシュで行う。
- **D4 条件**（どれも同じ本数 K_F、k = 0〜K_F − 1）：
  - **K_F の決め方（第4版）**：段A で件数が決まった時点で、{32, 40, 48} のうち 6. の段A の予算の確かめを通る**一番大きい値**にする。件数（W・C_W・A2 の数）と CR-2 の記録した count_tokens だけで決め、CR-3 の応答は 1 本も見ていない段階なので、結果によって選ぶことはない。32 でも通らなければ段A で止まる。選んだ値と、それぞれの値での確かめの式の値を段A の記録に書く。
  - **U(c)**：プリフィル P_c（CR-2 と同じ、何も足さない）。c は W の各単語の w − 1 と w の和集合 C_W（重なる切れ目は 1 回だけ頼む）。
  - **A1(w)**：プリフィル P_{w−1} + a1(w) の文字列。
  - **A2(w)**：プリフィル P_{w−1} + a2(w) の文字列（a2 がある単語だけ）。
  - プリフィルの末尾は空白でない（f は `\S` で終わる）。c = 0 のときは P_0 が空なので、プリフィルは別の単語だけ。
- **D5 リクエストと custom_id**：
  - custom_id は `c{ID:04d}-s{code}-k{kk}`（kk = 00〜K_F − 1）。code = 1000 × 種類 + 位置（種類 1 = U で位置は切れ目 c、2 = A1・3 = A2 で位置は単語 w）。CR-2 の `parse_custom_id` が読める形で、段の文字は 's' を使う。CR-2 の `custom_id` は 's' で k < 32 しか受け付けないので、CR-3 の custom_id は CR-3 の関数で同じ形に作る（読み取りは CR-2 の `parse_custom_id` で通ることを試験で確かめる）。
  - **リクエストの一覧は CR-3 の新しい関数**（`pork/cr3.py`）で作る。CR-2 の `manifest_rows`・`Requests` は P[c] しか作れないので使わない（code ≥ 1000 で壊れる）。CR-3 の一覧の各行は、custom_id・ユーザー文の sha256・プリフィルの sha256・モデル・最大トークン（CR-2 の `rows_hash` と同じ並び）。一覧のハッシュ（`manifest_sha256`）はこの行の並びから作る。
  - バッチの送受信・出し直し・欠け・予算の確かめは、CR-2 の `pork/cr2_g2.py` の状態の関数をそのまま使う。CR-3 の一覧の型は、CR-2 の `Requests` と同じ属性（`ids`・`params`・`stage`・`chunk_ids`・`n_chunks`・`distinct`・`batch_requests`・`manifest_sha256`）を持つ派生として作り、試験（9.）で、作り物の API に対して送信・集め・出し直し・欠け・予算の止まり方を確かめる。
  - バッチの見出し（`g2_header`）は段 's'・round 0・`future_requests` 0 で作り、あとから `"study_cr3": "CR-3"` と段A の記録のハッシュ `"cr3_lock_sha256"` を足す（見出しの `study` には CR-2 の定数が入るので、こちらで区別する）。
  - 1 つのバッチは 500 件（CR-2 の 2,000 件から変える。`pork/cr2_g2.py` の `CHUNK` を CR-3 の実行の中だけ置き換え、段A の記録と見出しに書く）。理由は 6.。
  - 結果のファイルは Drive の `DECISION_POINTS/cr3/` の下に置き、CR-2 のものと混ぜない。
  - **一覧の行（1 行ずつのプリフィルの sha256 を含む）は Drive（非公開）にだけ置き、Git には置かない**。Git に置くのは `manifest_sha256` と、D3 のまとめたハッシュと、数だけ（c = 0 の単語では、プリフィルが別の単語だけになり、1 行の sha256 から中身が分かるため）。
  - 同時に流すバッチは 4 つまで（CR-2 の `MAX_INFLIGHT` を CR-3 の実行の中だけ 4 にし、段A の記録と見出しに書く）。500 件 × 4 の最悪の額は約 $5.6 で、CR-2 の 2,000 件 × 2 より小さい。
- **D6 単語ごとの量**（「変わった」の割合。分母は戻ってきた応答の数）：
  - 答えの読み取りは、**そのリクエストのプリフィル全体＋続き**の全文から行う（A1・A2 では P_{w−1} + 別の単語 + 続き）。CR-2 の `build_sitem` は P[c] + 続きで読むので、CR-3 では使わない。
  - q_O(w) = U(w) の割合（元の単語 s_w を書いたあとからの続き）。
  - q_A1(w)・q_A2(w) = A1・A2 の割合。
  - **g_F(w) = q_A1(w) − q_O(w)**（一番多い別の単語を書かせたときの差。主の量）。
  - m_F(w) = U(w − 1) の応答のうち、新しい定義 10 で s_w を書かなかった割合。
  - u_F(w) = U(w − 1) の戻ってきた応答（最大 K_F 本）の最初の単位について、1 −（一番多い最初の単位の割合）（定義 14 と同じ比べ方。空は None の目印）。
  - u_F6(w) = 同じものを k = 0〜5 の 6 本だけで（CR-2 の u と同じ本数。副次）。
- **D7 欠け**：1 つの条件（U(c)・A1(w)・A2(w)）で、2 回の出し直しのあとも K_F 本中 ⌈0.875 × K_F⌉ 本（32 本なら 28、40 本なら 35、48 本なら 42）未満しか戻らなければ、その条件は「欠け」。その条件を使う量はその単語で NA。補わない。
- **D8 問題内の順位相関**（問2・問3 の主の値）：2 つの量 x・y が両方定義される単語について、問題ごとに x・y の順位 r（1〜n_i、同順位は平均）をつけ、z = (r − (n_i + 1)/2) / n_i とする（問題の中で中心化し、単語数で割る。これで各問題の重みはおおよそ単語数に比例し、単語の多い問題に偏らない）。全問題の z をまとめたピアソン相関を ρ_w(x, y) とする。単語が 1 語だけの問題は寄与しない。問題どうしの差（難しさ・q の水準）は入らない。

## 3. 問いとラベル

区間はすべて、**問題を単位にした**ブートストラップ（2,000 回、SEED_CR3_BOOT）の両側 95%。

- **問1（主。CR-2 の分かれ道は、書かせて測った差で再現するか）**：
  - 対象：W のうち g_F が定義される単語**だけに先に絞り**、その中に lab2 が真の単語と偽の単語の両方がある問題（AUROC の計算に NaN の単語を入れない）。
  - 値：問題内 AUROC（g_F で lab2 を見分ける。同点は 0.5）の問題平均と区間。
  - 検定：問題の中で lab2 を並べ替える（その問題の真の数は保つ）並べ替え検定。統計量は問題平均の AUROC、片側、R = 2,000、SEED_CR3_PERM。p = (1 + #{null ≥ 観測}) / (1 + R)。
  - ラベル：p ≤ 0.05 かつ区間の下限 > 0.5 → `FORCED_EFFECT_REPRODUCES_FORKS`。p ≤ 0.05 で下限 ≤ 0.5 → `FORK_REPRODUCTION_WEAK`。p > 0.05 → `FORK_REPRODUCTION_NOT_SHOWN`。対象の問題が 20 未満 → `Q1_INSUFFICIENT`。
  - 読み方：lab2 は CR-2 の応答で、g_F は CR-3 の新しい応答で決まる（互いに独立に引いた）。W と a1 は本数だけで選び、答えは見ていない。
    - 再現すれば「CR-2 の分かれ道のラベルは、一番多い別の単語を書かせたときに答えが変わりやすい単語と重なっていた」と書く。lab2 は d_s = m × g の上位なので、重なりは m・位置・元の単語のあとの変わりやすさ（q_O）を通しても生じうる。その切り分けは副次（S2・S8）で記述する。
    - 再現しなければ「書かせて測った差では再現しなかった」とだけ書く。g_F は一番多い別の単語 1 つだけを見ていて、CR-2 の g はすべての別の単語をまとめたものなので、「CR-2 のラベルは雑音だった」とは書かない。
- **問2（主。u は g を予測するか）**：
  - 値：問題内の順位相関 ρ_w(u_F, g_F)（D8）と、問題を単位にしたブートストラップの 95% 区間。ブートストラップの回で ρ_w が定義できない（順位の散らばりが 0）ものは除いて数を報告する。
  - ラベル（**上から順に当て、最初に当てはまったもの**）：
    1. 下限 > 0 → `U_PREDICTS_G`（上限が 0.15 未満なら「小さい」と添える）。
    2. 上限 < 0 → `U_G_NEGATIVE`。
    3. 区間が −0.15〜+0.15 に収まり、**かつ g_F の問題内の信頼性 R_w が 0.5 以上** → `U_G_NEGLIGIBLE`。R_w は、本番号の偶数・奇数で作った g_F の 2 つの半分に D8 を当てた ρ_w(g_F 偶数, g_F 奇数) から、スピアマン・ブラウン（2ρ/(1+ρ)、ρ ≤ 0 なら 0）で出す。
    4. それ以外 → `U_G_ASSOCIATION_NOT_SHOWN`。
  - 3. の条件の理由：g_F の雑音は ρ を 0 の方へ縮めるので、信頼性が低いときに「無関係」と言うと、雑音を無関係と取り違える。信頼性が足りないときは「つながりは示されなかった」とだけ書く。同値の判定に 95% 区間を使うのは、ふつうの 90% より厳しい。
  - 予想（見直しから）：`U_G_NEGLIGIBLE` か `U_G_ASSOCIATION_NOT_SHOWN`。
- **問3（主。別の単語が出る割合は g を予測するか）**：ρ_w(m_F, g_F)、ラベルは問2 と同じ順と条件（`M_PREDICTS_G`・`M_G_NEGATIVE`・`M_G_NEGLIGIBLE`・`M_G_ASSOCIATION_NOT_SHOWN`）。
- 問1〜問3 は別々の問いで、まとめた主張（「どれかが当たった」）はしない。多重性の補正はしない（3 つとも結果を全部書く）。
- 問2・問3 の値は、g_F の雑音で 0 の方へ縮む。副次 R で g_F・u_F・m_F の信頼性を出して添える（補正した値はラベルに使わない。信頼性は問2・問3 の 3. の条件にだけ使う）。

### ラベルの優先順（最初に当てはまったもので止める）

1. 段A・段B の前の照合で止まった → `STOPPED_BEFORE_RUN`。
2. 未完了 → `INCOMPLETE_NO_CONFIRMATORY_VERDICT`（問1〜問3 のラベルを出さない）：予算で止まった、終わりの状態が分からないリクエストがある、欠け（D7）で g_F・u_F・m_F のどれかが NA になった単語（a1 なしで g_F が NA の単語は数えない）が W の 10% を超えた。
3. 監査の失敗 → `PROTOCOL_AUDIT_FAIL_NO_CONFIRMATORY_VERDICT`。
4. 読めない応答 > 20%（CR-3 の全応答）→ `READOUT_UNRELIABLE_NO_CONFIRMATORY_VERDICT`。5〜20% はすべてのラベルに `READOUT_CAVEAT`。
5. それ以外 → 問1〜問3 のラベルを出す（`LABELS_ISSUED`）。

## 4. 副次（ラベルなし、記述だけ）

- **R 信頼性**：g_F・u_F・m_F を本番号の偶数・奇数で半分に分け、半分どうしの ρ_w（D8）とまとめたスピアマンの両方と、それぞれのスピアマン・ブラウンの信頼性。問2・問3 の 3. の条件には、g_F の ρ_w から出した R_w だけを使う。
- **S1 別の単語どうし**：A2 がある単語で ρ(g_A1, g_A2)（g_A2 = q_A2 − q_O）、|q_A1 − q_A2| の平均、問1 を g_A2 と (g_A1 + g_A2)/2 でも。
- **S2 CR-2 との再現**：ρ(m_F, CR-2 の m)、ρ(u_F6, CR-2 の u)、ρ(q_O, CR-2 の q_keep)、q_O − q_keep の平均（区間つき）。
- **S3 新しいデータでの分け方**：U(w − 1) の応答で d_F =（別の単語の応答のうち変わった数）/（戻ってきた本数）− m_F × q_O を作り、W の中で ρ(d_F, m_F)・ρ(d_F, g_F)。
- **S4 ほかの集め方**：問2・問3 を、(i) 全単語をまとめたスピアマン（問題どうしの差を含む）、(ii) W の単語が 3 語以上ある問題の問題内スピアマンの平均でも（区間つき）。
- **S5 深さの層**：問1〜問3 の値を深さ 2〜3・4〜5 で。種を単位にした区間を並べる（CR-2 と同じ作り）。
- **S6 読めない応答**：条件ごと・深さの層ごとの読めない応答と `max_tokens` の数。
- **S7 a1 なし**：a1 がない単語の数、A2 がある単語の数。
- **S8 g の測り直しと、自然に出た場合との比べ**：W の中で ρ(CR-2 の g, g_F)。U(w − 1) の応答のうち最初の単位（先頭の空白を落とす）が a1 だったものの「変わった」割合（自然に a1 が出た場合）と q_A1（書かせた場合）の比べ（単語ごとの差の平均と区間。自然に a1 が 4 本以上出た単語だけ）。
- **S9 くっつき**：U・A1・A2 の続きのうち、空でなく空白で始まらないものの割合（条件ごと）。A1 でこの割合が高い単語は、書かれた単語が a1 とつながって別の単語になっている。A1 の続きがくっついたものを除いた q_A1 で問1 を出し直す（感度、記述だけ）。

## 6. 予算

- 残高 $25.72（オーナー、2026-10-14 13:48）。
- **B_cap = $24**（残高から $1.72 の余裕）。**B_stop = $21**（止める線。下のすべての確かめに使う）。
- リクエストの数の上限（K_F = 32 のとき）：U は |C_W| × 32 ≤ 528 × 32 = 16,896、A1 は ≤ 264 × 32 = 8,448、A2 は ≤ 151 × 32 = 4,832（151 は見直しで別の単位が 2 種類以上あった単語。空を除くともっと少ない）。合計 ≤ 30,176。正確な数と K_F は段A で決まる（D4）。K_F = 40・48 なら件数はそれぞれ 1.25 倍・1.5 倍で、段A の予算の確かめを通る場合に限る。
- 見込み：1 件 $0.000489（CR-2 の G2c の実績、$10.20 / 20,880）で上限 $14.8、× 1.2 で $17.7。
- 送る前の確かめと途中で止める条件は CR-2 と同じ式（count_tokens × 1.1 と最大出力 1,024 トークンで最悪の額、使った額 + 流れているバッチの最悪の額 + このバッチの最悪の額 ≤ B_stop、残りの見込み × 1.2 が B_stop の残りを超えたら止める）。
- **使った額は CR-3 の支出だけを数える**（見出しの `prior_spent_usd` = 0）。
- CR-2 の仕組みは B_stop を `pork/cr2.py` の定数 `C.B_STOP` で、呼ぶたびに読む。CR-3 の実行の中だけ `C.B_STOP = 21.0` に置き換え、見出しに書き（`B_stop: 21.0`）、**送る輪の前に毎回 `C.B_STOP == 21.0` を確かめる**（ランタイムを替えると 54 に戻るため）。
- **バッチの大きさを 500 件にする理由**：2,000 件のバッチの最悪の額は約 $5.7（1 件の最悪 ≈ $0.0028）で、K_F = 32 の上限の 30,176 件でも最後のバッチを出す時点の使った額 ≈ $13.7 に最悪の額を足すと $19.4 になり、単価が見込みより 12% 高いだけで $21 を超えて止まってしまう。500 件なら最悪の額は約 $1.4 で、余裕が大きい。
- 段A の予算の確かめ（API なし）：N を CR-3 の件数、p = $0.000489（CR-2 の G2c の実績の単価）、w_max を 1 件の最悪の額（CR-2 の G2c の状態に記録した count_tokens の最大 + 16 トークンを入力とし、× 1.1、出力 1,024 トークン）として、N × p × 1.2 + 500 × w_max ≤ B_stop なら通る（流れているバッチがある間は、送れないバッチは待つだけなので、最後まで送れるかを決めるのは最後のバッチを単独で送れるかどうか。最終確認のレビューの指摘で 4 × 500 から直した）。通らなければ段A で止まる（計画を直す）。式の値はすべて記録する。
