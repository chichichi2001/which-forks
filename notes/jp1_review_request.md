## 見てほしいこと

- **R1 比べ方の筋**：同じモデルで言語だけを変えれば「言語の違い」と言える、という組み立てでよいか。訳の質の違い、日本語の道のトークン数が多いこと（位置の数が増える）、言語ごとの正解率の違いが、A4・B2 の差に混ざらないか。混ざるなら、どの副次（S5・S6・S8 など）で切り分けるべきか。
- **R2 日本語の答えの読み取り**：目印「答え」＋`:`/`：`、全角数字の読み替えで足りるか。「答えは12個」「答え：十二」のような書き方、単位つき、小数、MGSM の `answer_number` の型で、読み取りの失敗や採点の食い違いが起きないか。日本語での答えの先頭 a の決め方（全角数字を含む）に穴はないか。
- **R3 語の種類の決め方**：
  - 書いた側が気づいている心配：日本語の「数字」を「漢数字を**含む**語」としているので、「一緒」「一番」「十分」「万年筆」のような、数を表さない語まで数字になる。直すべきか、直すならどう書くのがよいか（例：UniDic の品詞「名詞-数詞」を使う）。
  - 英語の一覧の多義語（`left`「左」、`times`「回」など）、記号だけの語、`each` が NLTK の stopwords にも入っている点（計算を優先する順番で足りるか）。
  - トークンと形態素の境目が合わないとき（1トークンが2つの形態素にまたがる、など）の決め方で足りるか。
  - 付録C の例文で、G0 の確かめとして十分か（足りない種類の語はないか）。
- **R4 判定のラベル**：A4 の ±0.10、B2 の ±0.05 の線と、ラベルの決め方（重なり・抜け・順番）に穴はないか。B1 の「全部の位置の割合を引く」基準でよいか。言語をまとめたブートストラップのやり方で足りるか。
