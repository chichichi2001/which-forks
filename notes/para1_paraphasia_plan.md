## ひとことで（数式なしの要約）

- 人の言い間違い（錯語）には、大きく 2 つの型がある。
  - **形型**：形の似た語に置き換わる（Mario → Dario。オーナーの日本語の例では、りんご→たんご）。失語症の分け方では字性錯語・音韻性錯語に近い。
  - **意味型**：意味の似た語に置き換わる（cold → chilly。オーナーの日本語の例では、寒い→冷たい）。語性錯語・意味性錯語に近い。
  - オーナー自身、書くときは形型、話すときは意味型の置き換えが起きることがある。これが発想のもと。
- LLM でも、同じ場所から引き直すと、別の単語が出てくる（決定点の研究の「分かれ道」）。その置き換えは、意味型か、形型か、それともどちらでもない（文の組み立てが変わっただけ）か。
- **部A（Claude）**：CR-1 で集める「別の単語を引いた続き」を型に分ける。型ごとに、答えが変わりやすいかも見る。API の追加の費用はない。
- **部B（オープンモデル）**：中身の確率が見えるモデルで、サンプラー（温度・top-p・min-p・p-less など）を変えると、置き換えの型の割合がどう変わるかを計算する。部B が見るのは**「次の 1 トークン」とねらいの語の比べ（語の置き換えの近似）**で、語全体の置き換えではない。確率の量はサンプリングせずに計算するが、型分けできるのは確率の上位の候補だけなので、型の割合は「型分けできた部分の中の割合」と「全体での上下の幅」で出す。GodPork の「サンプラーの性質チェッカー」に新しい軸を足す形。
- 言い方の約束：
  - LLM の置き換えは、間違いとは限らない（別の正しい言い方のことが多い）。「LLM が錯語をした」とは言わない。言えるのは「置き換えの型の割合」まで。
  - 型の割合や、答えの変わりやすさとの関係は**結びつき**で、因果の主張はしない。
  - **意味型は「WordNet の規則で関連づけられる」という意味**（同義・上位/下位・仲間・反対語・形容詞の似た語）。反対語も入るので「意味が似ている」とは限らない。多義語では、その文脈でその意味が使われた証拠にもならない。本文では「WordNet で定義した語彙・意味の関連」と書く。
  - 「偶然より多い」とは言わない。言えるのは「同じ問題の中で、ねらいの語をずらして組み合わせた比較（ずらした比較）より多い」まで。
  - 型分けはコードが自動で行う。単語やトークンの中身は表示しない（数・ID・ハッシュだけ）。問題の中身も表示しない。
  - ここでの**形型は「つづり（文字）の似かた」**で、失語症の研究でいう音の似かた（音韻性の誤り・formal error）とは別のもの。LLM は文字の列を扱うので、つづりで測る。人の錯語と同じものを測っているとは言わない。

## 背景と開示

- 発想：オーナーが本屋で知った「錯語」と、自分の言い間違いの観察（2026-10-12、チャットでの雑談）。
- 先に調べたこと（2026-10-12。第1版で軽く、第2版で追加。arXiv の番号のあるものは、arXiv・会議のページで存在を確認した。人の言い間違いの古典の文献は書誌だけで、ページは確認していない）：
  - **人の言い間違いの研究**：単語の置き換えには、意味の似た語への置き換えと、形（音）の似た語への置き換えがあることは古くから知られている（Fay & Cutler 1977 の malapropism の研究、Dell 1986 の語の産出のモデル、失語症の呼称の誤りを意味性・形式性・混合・無関連・非語に分ける Philadelphia Naming Test の分類など）。PARA-1 の型の名前は、この分け方を借りている。ただし上に書いたとおり、PARA-1 の形型はつづりの似かたで測る。
  - **患者さんの錯語の自動分類**：患者さんの錯語を LLM などで自動分類する研究がある（例：arXiv 2407.11345、Fergadiotis らの分類）。PARA-1 は患者さんのデータを使わず、この方向はやらない。
  - **LLM を壊して失語症の誤り方を再現する研究**：Yang ら（arXiv 2607.11621、2026-07）は、画像と言葉のモデル（LLaVA 1.6、Vicuna-13B）の層の重みに雑音を入れ、絵の呼称の誤りの型の割合が患者さんの型の割合と合う設定があることを示した。型分けは専門家のラベルで学習した分類器で行い、**形式性の誤り（音の似た語）は患者さんよりずっと少なかった**と報告している。続く研究（arXiv 2608.06429）は、誤りの型の割合から壊し方を逆に推定している。どちらも貪欲法で、サンプラーや温度は変えていない。PARA-1 はモデルを壊さず、ふつうのモデルの引き直しの置き換えと、サンプラーによる違いを見る。型分けは WordNet とつづりの規則で決め、学習した分類器は使わない。
  - **語の置き換え（lexical substitution）**：文の中の語を言い換える課題で、モデルが出す置き換え候補とねらいの語の意味の関係（同義・上位語など）の種類を分析した研究がある（Arefyev ら、COLING 2020、arXiv 2206.11815）。これは「言い換えを出させる」課題で、PARA-1 は言い換えを頼まずに、ふつうの引き直しで自然に出る置き換えを見る点が違う。
  - **分かれ道の研究**：Bigelow ら（Forking Paths、ICLR 2025、arXiv 2412.07961）は、引き直しで答えが変わる「分かれ道のトークン」を見つけ、句読点のような意外なトークンが分かれ道になることもあると書いている。Wang ら（arXiv 2506.01939、NeurIPS 2025）は、エントロピーの高いトークンには "however"・"thus" のようなつなぎの語が多いと報告している。どちらも、分かれ道で**どんな型の置き換えが起きているか**は分けていない。PARA-1 はそこを型で分ける（決定点の研究 DP・CR-1 の続き）。
  - **意味の揺れと形の揺れ**：Kuhn ら（semantic entropy、ICLR 2023、arXiv 2302.09664）は、言い方だけ違って意味が同じ出力をまとめてから不確かさを測る。PARA-1 は、出力全体ではなく、引き直しの最初の 1 語の置き換えを、意味型・形型などに分ける。
  - **サンプラーと裾**：Hewitt ら（arXiv 2210.15191、EMNLP 2022 Findings）は、切り方のサンプラーを「確率の裾を削る」ものとして説明し、eta サンプリングを提案した。min-p（Nguyen ら、ICLR 2025、arXiv 2407.01082）は、温度を上げても文がくずれにくいと報告している。どちらも、削られる候補がどの型か（断片・意味型・形型）は数えていない。部B の B2・B3 はそこを確率から正確に数える。
  - 新しさの言い方：上の範囲では、「ふつうの LLM の引き直しで出る置き換えを、意味型・形型などに分け、サンプラーでその割合がどう動くかを確率から正確に数えた」研究は見つからなかった。ただし探した範囲は限られるので、「見つからなかった」までしか言わない。
- 予想は持っている（下の「予想」に書いた）。どちらに出てもラベルで報告する。
- 部A のデータは CR-1 のもの。CR-1 の主のラベル（主0〜主3）には一切触れない。部A は CR-1 の結果を見る前に決めた「追加の分析」として、CR-1 の結果ノートとは別に報告する。
- CR-1 が止まった（`STOPPED_*`・`INCOMPLETE_*`・`PROTOCOL_AUDIT_FAIL_*`・`READOUT_UNRELIABLE_*`）ときは、部A は `NOT_RUN_CR1_STOPPED` とし、止まった理由を書く。CR-1 が `INSUFFICIENT_FORK_SIGNAL` で止まったときは、部A はそのまま行う（部A は分かれ道のラベルを使わない）。

## 型の決め方（部A・部B で共通）

比べる 2 つの文字列：**ねらいの語 w**（土台の道でその位置に書かれた語）と、**置き換え a**（引き直しや別の候補で出た語）。

1. **そろえ方**：前後の空白（改行・タブを含む）を落とし、末尾の記号（`.,;:!?)"'` のどれか、続けて何個でも）を落とし、もう一度前後の空白を落として、小文字にする。
   - 「英字」は ASCII の a〜z だけ。「数字」は ASCII の 0〜9 だけ（アラビア数字以外の数字の文字は数字に数えない）。「英数字を含まない」の判定だけは Unicode の文字・数字で見る。
2. **型**：次の順に見て、最初に当てはまったものにする。いちばん先に、**w がそろえたあと英数字を含まない位置は `EXCLUDED_EMPTY_TARGET`（型分けしない。数を報告）**とする。

| 順 | 型 | 当てはまる条件 |
|---|---|---|
| 1 | 表記ゆれ | そろえたあと a と w が同じ |
| 2 | 空 | そろえたあとの a が、文字・数字（Unicode の英数字）を 1 つも含まない（空の出力・空白だけ・記号だけ。例：`...`、`(`） |
| 3 | 数字 | a か w のどちらかが数字（0〜9）を含む。さらに「両方が数字だけで、数字の列の編集距離が 1」を**数字・形**、それ以外を**数字・その他**に分ける |
| 4 | 活用 | どちらも英字だけで、WordNet の語形の解析で同じ見出し語を共有する（apple / apples、go / went、see / saw など）。見出し語は、4 つの品詞（名詞・動詞・形容詞・副詞）それぞれで NLTK の `wordnet._morphy`（例外の表を含む、すべての解析）が返すものの集まりとする |
| 5 | 機能語 | a と w の両方が、固定した機能語の一覧（NLTK の英語の stopwords、凍結時の版）に入る |
| 6 | 意味・形・両方 | 下の 2 つの判定で決める。意味だけ → **意味型**、形だけ → **形型**、両方 → **両方** |
| 7 | その他 | 上のどれでもない（文の組み立てが変わった、関係の薄い語、語の断片など）。うち、a が WordNet にも機能語の一覧にもない英字の列を**断片**として内訳に出す |

- **意味の判定**：a と w の両方が WordNet（NLTK の WordNet 3.0、凍結時の版）にあり、次のどれかを満たす：同じ synset を持つ（同義）、一方の synset が他方の synset の直接の上位語か下位語、同じ直接の上位語を持つ（仲間の語、例：car と truck）、反対語、**形容詞の似た語（similar_to、直接）**［決定6］。品詞はそろえない（すべての synset で調べる）。
  - synset は NLTK の `wordnet.synsets(語)`（品詞を指定しない）で取る。この関数は語形を解析するので、apples のような変化形は apple の synset を使う。
  - 上位語には、固有名詞の「インスタンスの上位語」（instance hypernym）も含める（例：Paris と London は同じ上位語「首都」を持つので仲間の語）。
  - 反対語は、synset の中のどれかの語に反対語の印があり、その相手の synset が他方の synset のどれかと一致するとき。
  - 「直接」だけを見るので、cat と dog（直接の上位語に共通がない）、dog と animal（2 段以上離れている）は意味型にならない。広げない理由：段を増やすと、ほとんどの名詞の組が意味型になるため。
  - 形容詞は WordNet で上位語を持たず、似た語（similar_to）でつながっている。similar_to を入れないと、看板の例の cold → chilly も「その他」になる（第2版で確かめた）。
- **形の判定**：両方が英字だけで、長さがどちらも 3 文字以上、かつ次のどちらか：編集の似かたが 0.5 以上（1 − 編集距離 / 長い方の長さ）、または先頭の 3 文字が同じ。
- 編集距離は自前の実装（レーベンシュタイン距離。入れ替え（from / form）は 2 と数える）。外部のパッケージは使わない。
- 順のため、機能語どうしでも語形を共有するもの（is / was）は「活用」になる。
- 型分けのコード：`scripts/para1_typing.py`（第2版で作成、第3版で部B の候補の型分け、第4〜5版でデコードの関数を追加）。凍結の記録の blob で固定した。
- **［決定6］の感度分析（必ず出す）**：本番の型分けは similar_to を**入れる**。あわせて、similar_to を**入れない**型分けでも A1・A2・B1・B2・B3 を計算し、副次（ラベルなし）として必ず並べて報告する。similar_to によってだけ意味型・両方になった件数と量も記録する。反対語・similar_to など、意味型になった理由は個別に残す。

**ずらした比較（不対応の基準。記述のための基準）**
- 目的：「置き換え a と、その場のねらいの語 w の組み合わせ」で見た型の割合が、「同じ問題の中で、w だけを別の位置のものにずらした組み合わせ」で見た割合と比べて多いかを記述する。**これは「偶然」の割合ではない。** w をずらすと、意味の関係だけでなく、品詞・長さ・文脈なども一緒に動くため。
- **層**：w を次の 4 つの層に分け、**同じ問題の、同じ層の中だけで** w をずらす。
  - 数字の層（w が ASCII の数字を含む）／機能語の層（w が機能語の一覧にある）／WordNet の層（w が英字だけで、WordNet にあり、機能語でない）／残りの層。
- **まとまりごとに動かす**：部A では、同じ切れ目の続き（何本あっても）はまとめて 1 つとして、切れ目ごとに w をずらす（同じ切れ目の応答どうしの結びつきを崩さないため）。部B では、位置ごとの候補の分布はその位置に置いたまま、位置ごとに w をずらす。
- **ずらし方（一対一、元の場所には戻さない）**：問題ごと・層ごとに、ずらせる位置（部A では切れ目、部B では位置）を番号の小さい順に並べ、**一様な乱数で選んだ「どれも元の場所に戻らない並べ替え」（完全順列）**で w を入れ替える。作り方は、`numpy.random.Generator(PCG64)` の `permutation` を引き、元の場所に戻る位置が 1 つでもあれば引き直す（棄却法）。同じ w の文字列が別の位置にもある場合は、入れ替えても同じ文字列になりうる（その件数を報告する）。
- 乱数の決め方：問題を問題 ID の順に並べた番号を i として、`numpy.random.default_rng([SEED_PARA_PERM, i])` を問題ごとに作る。1 回のずらしの中では、層を「数字 → 機能語 → WordNet → 残り」の順に処理し、2,000 回をこの順でくり返す（乱数を使う順を固定する）。部B はモデルごとに同じ決め方で、`default_rng([SEED_PARA_PERM, i, モデルの番号（OLMo = 1、Gemma = 2）])` を使う。
- ずらせない場合：問題の中で、その層の位置が 1 つしかないときは、その位置は比較に入れない（数を報告）。比較に入る位置が 1 つもない問題は、ずらした比較の対象外（数を報告）。
- 回数と集約：問題ごとに 2,000 回ずらし（SEED_PARA_PERM）、型ごとの割合の**平均**を、その問題の「ずらした比較の割合」とする（モンテカルロの標準誤差も報告する）。テンプレートを単位にしたブートストラップでは、問題ごとの（観測 − ずらした比較）をそのまま再標本化し、ブートストラップのたびにずらし直さない。この区間は並べ替え検定の p 値ではない。
- **偽陽性の確かめ（G0c）**：データの前に、人工の世界で、**部A と同じ手順を最初から最後まで**通して確かめる。
  - 語の表（固定。ベンチマークとは関係ない）：数字の層＝`0`〜`200` の文字列、機能語の層＝凍結時の stopwords の一覧、WordNet の層＝WordNet 3.0 の見出し語のうち ASCII の英字だけで 3〜10 文字・機能語でないものから、`default_rng([SEED_PARA_PERM, 999999])` で選んだ 2,000 語、残りの層＝同じ乱数で作った 4〜6 文字の英字の列のうち WordNet にも機能語の一覧にもないもの 200 個。表は並べて改行でつなぎ、SHA256 を記録する。
  - 1 つの世界：100 問 × 切れ目 20。各切れ目の w を、語の表全体から一様に選ぶ。各切れ目で組B の続きを 5 本作り、それぞれ確率 0.5 で「w をそのまま書いた」とし（続きの文字列は w で始まる）、残りは**w と同じ層の語を、w と無関係に一様に選んだもの**を最初の単位にする。
  - そのあと部A と同じく、CR-1 の定義 10 の前方一致（続きが w で始まれば「そのまま書いた」側に入る。たまたま w で始まる語も入る）、`EXCLUDED_EMPTY_TARGET`、型分け、ずらした比較、テンプレート（ここでは 1 問 = 1 テンプレート）を単位にしたブートストラップ、判定の順（500 本・30 問の条件）を、本番のコードのまま通す。
  - 世界を 200 個（世界の番号は 0〜199、`default_rng([SEED_PARA_PERM, 888888, 世界の番号])`）作り、3 つの型それぞれで `<型>_ABOVE_MISMATCH_BASELINE` が出た割合を数える。どれかが 0.075 を超えたら、A2 のラベルは出さず記述だけにする（`A2_NOT_CALIBRATED`）。
  - G0c の記録：語の表の SHA256 と並べ方、numpy・NLTK の版、世界ごとの「層ごとの位置の数」の分布、ずらした比較に入れなかった問題の数、3 つの型それぞれの偽陽性の割合。
  - G0c が通っても言えるのは「この人工の世界（層の中で w と a が無関係）に対しては、ラベルの出すぎがなかった」までで、実データでの並べ替え検定の p 値や、あらゆる無関係な世界での保証にはならない。
- 限界：人工の世界は「層の中では w と a が無関係」という場合しか試せない。品詞や文脈を通じた結びつきは残りうるので、A2 は「ずらした比較より多い」までしか言わない。

## 部A：Claude の引き直しの置き換え（CR-1 のデータ）

### 対象
- CR-1 の主の分析に入った問題・切れ目（CR-1 の欠けの扱いのあと）。
- 組B の戻ってきた応答のうち、単語 w をそのまま書かなかったもの（CR-1 の定義 10・11 の「別の単語を引いた」続き）。

### 問い
- **A1（記述）**：型ごとの割合。重みは「別の単語を引いた続き 1 本ずつ」（`EXCLUDED_EMPTY_TARGET` の位置は除く）。問題ごとに割合を出し（別の単語を引いた続きが 1 本以上ある問題だけ）、問題の平均と、テンプレートを単位にしたブートストラップの 95% 区間（2,000 回、SEED_PARA_BOOT）。組A でも同じものを出す（上の選び方）。
- **A2（ずらした比較より多いか）**：意味型・形型・両方のそれぞれについて、**超過** =（観測の割合）−（ずらした比較の割合）。どちらも、ずらした比較に入る位置の続きだけで数える。問題ごとに出し、テンプレートを単位にしたブートストラップの 95% 区間。3 つの型を別々に報告し、どれか 1 つだけを取り出して主張しない。
- **A3（どの型が答えを変えやすいか）**：別の単語を引いた続きのうち答えが変わった割合を、型ごとに出す。主に比べるのは次の 2 つの差：
  - （数字・形 と 数字・その他 をあわせた**数字**）−（意味型）
  - （形型）−（意味型）
  - 問題ごとに、両方の型が 1 本以上ある問題だけで差を出し（**条件つきの比べ**）、テンプレートを単位にしたブートストラップの 95% 区間。2 つの差で対象の問題が違ってよい。それぞれ、対象の問題数、型ごとの続きの数と答えが変わった数、全体の問題数、外した問題数を報告する。対象が 30 問未満なら、その差は `A3_INSUFFICIENT`。
  - これは結びつきで、「数字を書き換えたせいで答えが変わった」とは言わない。

- A2（意味型・形型・両方それぞれ）：下限 > 0 → `<型>_ABOVE_MISMATCH_BASELINE`。上限 < 0 → `<型>_BELOW_MISMATCH_BASELINE`。それ以外 → `<型>_NOT_DISTINGUISHED_FROM_MISMATCH_BASELINE`。

## 部B：オープンモデルとサンプラー（次の 1 トークンで見た置き換えの近似）

### 何を測るか（はっきりさせること）
- 部B が測るのは、**語の始まりの位置で、貪欲法のトークン g 以外の「次の 1 トークン」v の文字列と、土台の道のねらいの語 w の比べ**。1 トークンは、語全体のことも、語の先頭の一部のことも、記号・空白・複数の語のこともある。したがって部B の型は**「次のトークンで見た置き換えの近似」**で、語全体の置き換えとは呼ばない。
- 語全体を作る（v のあとを続けて生成する）方法は使わない。続け方をどう決めても近似が増え、「確率から計算する」ことが崩れるため。
- 確率の量（置き換えの量、型ごとの量、裾）は、サンプリングせずに全語彙の確率から計算する。ただし型分けするのは上位の候補だけなので、型の割合は下の「被覆」と「上下の幅」をつけて出す。

### モデルと問題
- モデル：`allenai/OLMo-2-0425-1B-Instruct`（DP4 と同じ）、`google/gemma-2-2b-it`（DP5 と同じ）。モデルの重みとトークナイザーの revision（Hugging Face のコミット）を凍結時に記録する。
- 問題：GSM-Symbolic の 100 テンプレートから 1 問ずつ。選び方は CR-1 の定義 1 と同じ除外の連鎖・同じ乱数種 SEED_ITEM の順の、最初の候補（Claude の土台の道の条件は使わない）。
- 土台の道：DP3 と同じプロンプト・採点。貪欲法（確率の大きい順、同じなら番号の小さい順）、最大 512 トークン。答えが読めない問題は外して数を報告する。
- 対象の位置：土台の道のうち、最初の `####` を含む行より前で、**語の始まりのトークン**の位置。語の始まり＝そのトークンの文字列（下の「トークンの文字列」）が空白（改行・タブを含む）で始まる、または応答の最初のトークン。
- ねらいの語 w：その位置のトークンから、次の語の始まりのトークンの手前まで（または `####` の行の手前まで）の土台の道のトークンを、まとめてデコードした文字列（CPU のノートブックで、保存したトークン ID から作る）。

### トークンの文字列（デコードの決まり）
- 候補 v の文字列は、**トークナイザーの公式の `decode` を、前の文脈と一緒に使って作る**（文脈つきの差分）：窓＝その位置の直前の土台の道のトークン（最大 8 個。応答の最初では 0 個）として、text(v) ＝ decode(窓 ＋ [v]) から、先頭の decode(窓) を取り除いたもの。`decode` は `skip_special_tokens=False`、`clean_up_tokenization_spaces=False` で呼ぶ。OLMo・Gemma のトークナイザーの中身（`Ġ`・`▁`・バイトの表）を自前で扱わない。
- decode(窓 ＋ [v]) が decode(窓) で始まらないとき（窓の最後がバイトの途中だった場合など）は、その候補を**デコード不一致**とする（部B 固有の型。量を報告する）。
- 「空白で始まる」＝ text(v) の最初の文字が空白（Unicode の空白。改行・タブを含む）。「特別」＝ v が `tokenizer.all_special_ids` に入る。どちらも関数の中でトークン ID から決め、呼び出す側からは渡さない。
- ねらいの語 w も同じ決まりで作る：decode(窓 ＋ w の範囲のトークン) から decode(窓) を取り除いたもの。**decode(窓 ＋ w の範囲のトークン) が decode(窓) で始まらないときは、w を作らず、その位置を丸ごと `EXCLUDED_TARGET_DECODE_MISMATCH` として外す**（ほかの方法で w を作り直さない）。
- CPU のノートブックでは、トークン ID → w と候補の文字列 → 型、を 1 つの接続の関数（試作の `type_position_candidates`）で行い、文字列や「空白で始まる」などを手で渡さない。
- 語の始まりの位置の判定（上の「対象の位置」）にも、同じ text(・) を使う。
- 試作：`scripts/para1_typing.py` の `decode_candidate`（凍結前は、おもちゃのトークナイザーでしか試していない）。

### 候補の型の順（部B 固有。上から先に決める）
貪欲法のトークン g 以外の候補 v（g と同じ文字列の別のトークンも含む）を、次の順で 1 つの型か除外に決める。
1. （**位置ごとの除外**。先に `EXCLUDED_TARGET_DECODE_MISMATCH`（w がデコードの決まりで作れない）、次に `EXCLUDED_EMPTY_TARGET`（w が英数字を含まない）。これらの位置は**位置ごと対象外**で、その位置のすべての候補の量を、型の量・別の切り方・裾・M_S・被覆の分母のどの集計にも入れず、帳尻の確かめ（G1）と G3 の監査の対象の位置からも外す。除外の理由ごとに、位置の数と M_S の合計だけを別に報告する。この M_S は **G2 で除外した位置についても logit と 12 条件のサンプラーを計算して得る、診断のためだけの値**で、上位 1,000 個の保存・型分け・被覆・分母・帳尻・G3 の監査の対象には入れない（除外した位置で保存するのは、除外の理由と 12 条件の M_S だけ）。除外した位置の一覧は G1b の固定の一覧で決める。）
2. **特別**：特別なトークン。
3. **デコード不一致**：上の「デコードの決まり」で文字列が作れない。
4. **バイト片**：文字列が U+FFFD を含む。
5. **空**：そろえたあと英数字を含まない（空白だけ・改行だけ・記号だけ。例：`,`）。
6. **くっつき**：空白で始まらない（前の語にくっつく。例：w = cat で `ca`）。
7. 複数の語を含む（空白で区切ると 2 つ以上）ときは、最初の単位だけを a とする（部A の `\s*\S+` と同じ）。数を報告する。
8. **別の切り方（除外）**：そろえた a が、そろえた w の真の先頭部分（a ≠ w。例：w = cat で ` ca`、` c`）。語の置き換えではないので型の割合から外し、量を報告する。
9. 上の「型の決め方」の順（表記ゆれ → 空 → 数字 → 活用 → 機能語 → 意味・形・両方 → その他）。
- 例（G0b で確かめる）：w = cat で ` cats` は活用（cats は cat の先頭部分ではない）、` Cat` は表記ゆれ。w が `...` なら、特別なトークンや U+FFFD の候補でも、位置ごと対象外。

### 計算（サンプリングしない）
- 演算の型：モデルの logit は float32 で取り、**すぐに float64 に上げてから**、温度で割り、GodPork の `REFERENCE_SAMPLERS`（凍結時のフルのコミット SHA に固定）で残す候補の集まり K_S と、残った中での確率 q_S を全語彙で計算する。同点の扱いは GodPork の実装のまま。
- CPU 側での確率の作り直し：上位 1,000 個の q_S は、保存した float32 の logit と、GPU で全語彙について計算した float64 の対数の分母（温度ごとの logsumexp）と、切り方のサンプラーごとの残った確率の合計から、CPU で float64 で計算し直す（GPU の値との差は帳尻の許容に入る）。
- 使うサンプラー（12 条件）：`temperature_only`（温度 0.7・1.0・1.3）、`top_k_40`、`top_p_0.95`、`min_p_0.05`、`eta_0.0009`、`epsilon_0.0003`、`typical_0.95`、`top_nsigma_1.0`、`min_k_3.0`、`p_less`。切り方の 9 つは温度 1.0。`REFERENCE_SAMPLERS` にある `greedy`・`mirostat_v2_mu10` は使わない。
- **置き換えの量**：M_S = Σ_{v ∈ K_S, v ≠ g} q_S(v)（全語彙）。
- **型分けする候補**：温度 1.0 の確率の上位 1,000 個（g を除く）。このうち K_S に入るものを型分けする。
- **裾**：tail_S = M_S −（上位 1,000 個のうち K_S に入り、g でないものの q_S の合計）。裾は**未分類**で、型の中身は分からない（中には別の切り方も入りうる）。
- **数の比べの許容（G1・G3 で共通）**：2 つの量 x・y は、|x − y| ≤ max(1e-12, 1e-9 × max(|x|, |y|)) のとき一致とする（0 どうしでも割り算をしない）。ID・順位・残すかどうかの真偽は、ずれ 0。
- **裾の計算**：tail_S は引き算で出すので、丸めで小さな負の値になりうる。−1e-12 以上の負の値は 0 とし、その件数と最小値を記録する。−1e-12 より小さい負の値が出たら、計算の誤りとして止める（`PROTOCOL_AUDIT_FAIL`）。`top_k_40` のように、残る候補がすべて上位 1,000 個に入るときは、裾は 0 になるはず。
- logsumexp：全語彙の float64 の配列（float32 の logit を float64 に上げ、温度で割ったもの）に対して、`torch.logsumexp` を float64 で計算する。
- 帳尻：各位置・各サンプラーで、Σ（型ごとの量）＋（別の切り方の量）＋ tail_S と M_S が、上の許容で一致すること。
- **被覆**：問題ごとに typed_coverage_S =（全位置の型ごとの量の合計）/（全位置の M_S −全位置の別の切り方の量）。裾の割合も出す。
- 上位 1,000 は温度 1.0 の順位で決めるので、温度 1.3 などでは被覆が下がりうる。被覆はサンプラーごとに報告する。

### GPU → CPU の保存の形（数字だけ。文字列は保存しない。大きさを抑える）
- 実行ごと：モデル名と revision、トークナイザーの revision、GodPork のコミット SHA、プロンプトのテンプレートの ID とハッシュ、演算の型の決まり、torch・transformers の版、GPU の種類。
- 問題ごと：問題 ID（ハッシュ）、土台の道の全トークン ID、答えの採点結果、対象の位置の番号の一覧と、それぞれの w の範囲（トークンの番号の始まりと終わり）。
- 位置ごと（本番）：g、上位 1,000 個のトークン ID（int32）、その **float32 の logit**（確率は保存せず、上の決まりで CPU で作り直す）、温度 0.7・1.0・1.3 の全語彙の logsumexp（float64）、切り方の 9 サンプラーで残るかどうか（上位 1,000 個についての真偽を 1 ビットずつに詰める）と、残った確率の合計（float64）、各サンプラーの M_S と tail_S（float64）、K_S の大きさ。
  - 大きさの見込み：1 位置あたり約 9 KB。1 モデルで 150 MB くらい（確率を float64 で 3 つ持つより約 4 分の 1）。
- **監査用（案A）**：G3 の対象（下の「G3 監査」で G2 の前に決める）の位置だけ、本番のときに**全語彙の float32 の logit をそのまま保存する**。
  - 大きさを抑える工夫：(1) 監査の問題は 5%（約 5 問）だけ。(2) その中で、対象の位置を最大 32 個に絞る（下の決め方）。(3) 保存は**情報を落とさない圧縮**（バイトの並べ替え＋zstd などの可逆圧縮。float16 などに丸めない）。(4) 各位置の配列の SHA256 を一緒に保存し、読み直したときに壊れていないことを確かめる。
  - 大きさの見込み：圧縮前で Gemma（語彙 約 25.6 万）が約 160 MB、OLMo（語彙 約 10 万）が約 65 MB。圧縮で少し小さくなる。

### 問い
- **B1（記述）**：モデルごと・サンプラーごとに、次の 2 つの形で型の割合を出す。
  - **型分けできた部分の中の割合**：問題ごとに（全位置のその型の量の合計）/（全位置の型ごとの量の合計）。問題の平均と、テンプレートを単位にしたブートストラップの 95% 区間。B2・B3 はこちらを使う。
  - **全体での上下の幅**：問題ごとに［その型の量 /（M_S −別の切り方の量）、（その型の量 ＋ 裾）/（M_S −別の切り方の量）］。問題の平均で出す。
  - 部B 固有の型（特別・デコード不一致・バイト片・くっつき）と別の切り方の量も同じ形で出す。
  - 分母が 0 の問題（型ごとの量の合計が 0、または M_S −別の切り方の量が 0）は、割合を 0 とせず **NA** とし、問題の平均から外す。NA の問題の数と理由を、モデル × サンプラーごとに報告する。
  - ずらした比較（上の層の中で、位置ごとの候補の分布はそのままで w をずらす）も、型分けできた部分の中の割合で出す（記述だけ。ラベルなし）。
- **B2（切り方のサンプラーで型の割合が変わるか）**：切り方の 9 サンプラー S について、意味型・形型・その他（断片を含む）の、型分けできた部分の中の割合の差 =（S）−（`temperature_only` 温度 1.0）。モデルごとに、両方で分母が正の問題だけで、テンプレートを単位にしたブートストラップの 95% 区間。
- **B3（温度）**：温度 1.3 と 0.7 の、温度 1.0 との差（B2 と同じ形）。
- 比べの数：2 モデル × 11 の比べ（切り方 9 ＋ 温度 2。温度 1.0 は基準なので自分とは比べない）× 3 型 ＝ 66 個。B2 と B3 は重ならない。

### 判定（事前に決めるラベル）
- 判定の順（上から先に決める。モデル × S ごと）：
  1. G1・G3 で止まった → ラベルを出さない（`PROTOCOL_AUDIT_FAIL` など）。
  2. **比べの対象の問題**＝その S と基準（温度 1.0）の**両方で**分母が正の問題（共通の集まり）。外した問題の数と理由を報告する。共通の集まりが 50 問未満 → `B_TOO_FEW_ITEMS`。
  3. 被覆が足りない：**上の共通の集まりの中で**、その S か基準のどちらかの typed_coverage の中央値が 0.90 未満 → `B_TYPE_COVERAGE_INSUFFICIENT`（その比べの 3 型のラベルを出さず、上下の幅だけを報告）。区間もこの共通の集まりで計算する。
  4. それ以外は下のラベル。
- B2・B3（モデル × S × 型ごと）：区間が −0.02〜+0.02 に全部収まる → `NO_SHIFT`。下限 > +0.02 → `SHIFT_UP`。上限 < −0.02 → `SHIFT_DOWN`。それ以外 → `SHIFT_UNDECIDED`。
  - `NO_SHIFT` は「±0.02 の幅の中に収まった」という狭い意味で、`SHIFT_UNDECIDED` を「変わらなかった」と読まない。
  - 0.02 は「割合が 2 ポイント動いたら意味がある」とする、実用上の線。
  - B2・B3 のラベルは**「型分けできた部分の中の割合」についてのもの**（ラベルの後ろに `_AMONG_CLASSIFIED` と添えて報告する）。被覆が 0.90 以上でも、裾の中身しだいで全体の割合の向きは逆になりうるので、全体の割合が上がった・下がったとは言わない。全体については B1 の上下の幅だけを示す。
- 66 個のラベルは、事前に決めたものを**全部**報告する。大きいものだけを取り出さない。記述的な要約として読む。

  - **logit の位置の決まり**：input_ids ＝ プロンプトのトークン ID（チャットのテンプレートと BOS を含めた、G1b で保存したものそのまま）＋土台の道のトークン ID とし、Hugging Face のふつうの因果言語モデルとして 1 回で順に通す。土台の道の t 番目（0 から数える）のトークン g_t を予測する logit は、`outputs.logits[0, len(プロンプトのトークン ID) + t − 1, :]`。t = 0（応答の最初のトークン）は、プロンプトの最後の位置の logit。プロンプトの長さはトークン ID のファイルに一緒に保存し、G2 では足し直さない。
  - **位置の対応の確かめ（G1 で行う。主の確かめ）**：G1 の 2 問で、(1) プロンプト＋土台の道の最初の t 個を入れて**1 つずつ**取った次のトークンの logit と、(2) G2 と同じく**一括で**取った上の位置の logit を、すべての対象の位置で、**ベクトルごと**比べる（最大の差、上位 20 個の ID と順位の一致）。最大の差は 1e-3 以下で、上位 20 個の ID と順位は、同点を除いて一致すること。あわせて、(3) わざと 1 つずらした位置（t − 1 と t + 1）の logit と比べると、ずれが大きく出ること（負の対照。上位 20 個の ID が全部は一致しない位置が出ること）、(4) 同じトークンが続く、無害な人工のトークン列（例：同じ ID を 8 個並べたもの）で、位置の式どおりに取り出せていること（各位置の logit のベクトルが、1 つずつ取った logit と一致すること）、を確かめる。どれかが通らなければ G1b に進まない。
    - 負の対照の扱い（確認レビュー 42da64b の止めない注意を凍結の前に入れた）：t − 1 が存在しない位置（t = 0）と t + 1 が存在しない位置（最後）は、それぞれその向きの負の対照から外す。位置が正しくても、上位 20 個がたまたま続いて負の対照で差が出ないことがありうるので、(3) で差の出る位置が 1 つもなかったときは「実装が壊れている」と決めつけず、`NEGATIVE_CONTROL_UNINFORMATIVE` として止め、記録する（(1)・(2)・(4) が通っていても G1b に進まない。原因を別のファイルに書き、オーナーが判断する）。
  - 補助の診断（G2 でも出す）：各問題の全部の位置で「logit の位置 t の最大のトークン ＝ 土台の道の t 番目のトークン」の一致率（下の `BASELINE_ARGMAX_MISMATCH` と同じ数え方）。これは位置の対応の証明ではない（同じトークンが続くと、1 つずれていても一致率は下がらない）。
  - **非有限の値**：logit・logsumexp・M_S・tail_S のどれかに NaN か無限大が出たら、その場で止める（`PROTOCOL_AUDIT_FAIL`）。除外した位置の診断の M_S にも同じく当てる。比べの許容の式は NaN を一致としない。G1 で、人工の NaN・無限大を入れて本当に止まることを確かめる。
  - 除外した位置の診断の記録は、対象の位置の記録とは別のファイル・別の集計にする。G1 で、診断の M_S が主の集計に入らないことを確かめる。
  - g は G1b で固定した土台の道のトークンとする。G2 で計算した logit の最大のトークンが g と違う位置があれば（GPU の計算の揺れ）、`BASELINE_ARGMAX_MISMATCH` として件数を報告する。その位置も g は固定したまま計算する。件数が対象の位置の 1% を超えたら、部B は記述だけにし、ラベルを出さない。1% 以下でも、件数・同点だったかどうか・最大のトークンと g の logit の差の最大値を報告し、結果は「固定した貪欲法の土台の道の g との比べ」と書く。
- **G3 監査**（案A）：
  - 監査の対象は **G1b で決めて、G2 の前の固定の一覧に入れる**：G1b で残った問題を問題 ID の順に並べ、`default_rng([SEED_PARA_AUDIT, モデルの番号])` で 5%（端数は切り上げ）を選ぶ。各問題の中では、位置ごとの除外のあとの対象の位置を番号の順に並べ、`default_rng([SEED_PARA_AUDIT, モデルの番号, 問題の番号])` で最大 32 個を選ぶ（32 個以下なら全部）。モデルごとに別の一覧になる。
  - 監査は、全部の位置の確かめではなく、5% の問題の最大 32 位置の**部分の確かめ**であることを、結果にもそう書く。
  - 本番（G2）で、その位置の全語彙の float32 の logit を保存する（上の「監査用」）。
  - **主の確かめ**：GodPork を使わずに別に書いた参照の実装で、**保存した本番の logit から**、K_S（上位 1,000 個の中の真偽）、残った確率の合計、logsumexp、M_S、tail_S、上位 1,000 個の ID と順位を計算し直し、本番で保存した値と比べる。真偽・ID・順位のずれは 0、量は上の「数の比べの許容」で一致すること。型分けも、別に書いた参照の型分けで計算し直し、ずれが 0 であること。ずれがあれば `PROTOCOL_AUDIT_FAIL`（部B のラベルを出さない）。
  - **再現性の確かめ**：GPU でその位置の logit をもう一度取り直し、保存した本番の logit との最大の差を測る。1e-4 以下ならそのまま。1e-4 を超え 1e-2 以下なら `AUDIT_LOGIT_DRIFT_MINOR`（報告だけ。主の確かめが通っていればラベルは出す）。1e-2 を超えたら `AUDIT_LOGIT_DRIFT_MAJOR`（土台の道や順位が変わりうる大きさなので、部B は記述だけにし、ラベルを出さない）。
  - 主の確かめは保存した本番の logit から行うので、取り直しの差があっても「本番の数字が、本番の logit から正しく計算されたか」は確かめられる。取り直しの差は、同じ実行をくり返したときに同じ logit が出るか（再現性）の確かめ。
